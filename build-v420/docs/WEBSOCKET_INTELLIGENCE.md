# SENTINEL v4.1.0 — محرك WebSocket الذكي

> المرجع التنفيذي لـ `websocket.py` — عميل RFC 6455 كامل بلا تبعيات + طبقة ذكاء آمنة.

## لماذا وحدة جديدة؟

مكتبة بايثون القياسية **لا تحتوي عميل WebSocket**. v4.1.0 يشحن تنفيذًا ذاتيًا:

- **المصافحة**: GET Upgrade + Sec-WebSocket-Key (RFC 6455)
- **التأطير**: ترميز/فك ترميز إطارات العميل (masked) والخادم، أطوال 7-bit/16-bit/64-bit
- **التحكم**: ping→pong فوري، close بنظافة، تجميع الإطارات الممتدة
- **سقف أمان 1MB للإطار** (إطار 8MB من هدف خبيث يُرفض دون انهيار — مثبت اختباريًا)
- **استهلاك جزئي صحيح للـleftover** (إطارات متلاصقة في مقطع TCP واحد — خطأ
  التقطته الحملة وأُصلح)

## خط الأنابيب

```
DISCOVER → CONNECT (scope-gated) → LISTEN (passive) → CLASSIFY protocol
        → TEST (planner-gated) → BOUNDARY
```

### الاكتشاف
1. روابط `ws://`/`wss://` المستخرجة من JS — **V411-WS-DISC-2 (مُلتقطة حيًا على
   DVWS)**: التطبيقات الحقيقية تحتفظ بعنوان القناة في **متغير JavaScript**
   (`var wsUri = "ws://127.0.0.1:8080/command-execution"; new WebSocket(wsUri);`)
   ويستمع خادم WS غالبًا على **منفذ مختلف** عن أصل HTTP (DVWS: الويب 8888 /
   WS 8080). أي نص `ws://`/`wss://` مُقتبس في JavaScript التطبيق نفسه (سكربتات
   مضمّنة أو أصول JS) هو قناة **مُلاحظة** — ويغطي ذلك المتغير والمُنشئ الحرفي
   وكائنات الإعداد معًا. سجلات ذكاء JS (أشكال الرسائل + القنوات المُلاحظة)
   **تُصفَّر لكل فحص**.
2. استقصاء قائمة معروفة حتمية على أصل الهدف
3. **بوابة النطاق قبل أي اتصال**: العميل يتكلم مقابس خام — تتجاوز بوابة HTTP
   بحكم البنية، لذا يُفحص النطاق هنا: قناة على مضيف آخر = حد
   `BLOCKED_BY_SAFETY` **دون محاولة اتصال** (مثبت اختباريًا على ws://evil.invalid).
   القناة على **نفس المضيف بمنفذ مختلف** داخل النطاق — المُصرَّح به هو المضيف،
   ويُسجَّل فرق المنفذ في provenance القناة.
4. **canary الانعكاس أبجدي [a-z0-9] فقط** (V411-WS-CANARY، مُلتقطة حيًا على
   DVWS): قناة /command-execution تُلحق الرسالة الخام بـ
   `shell_exec('ping -c 3 ' . $msg)` و/file-inclusion يمررها إلى
   `file_get_contents()` — الكناري لا يحمل أي محرف shell أو فاصل مسار أو
   بادئة wrapper أو صيغة قالب: **عاجز بالبناء** في كل سياقات الحقن، ويبقى
   قابلًا للإثبات عند الانعكاس.

**الإثبات الحي (DVWS، حالة نظيفة، --logic-active)**: 12/12 قناة مكتشفة
بمصدر `observed-js`، 12/12 مصافحة ناجحة، 77 اختبارًا عبر 86 اتصالًا، 9 قنوات
طلب/استجابة صُنّفت `text/request-json` (الإلهاب `{}` → أشكال JS →
connection_init)، وقناتا جلسة PHPSESSID رفضتا الصمت دون جلسة (فرض مصادقة
على مستوى القناة)، وقناة command-execution أُغلقت من الخادم (بيئة بلا ping)
— كلها حدود صادقة، لا تخمين.

### تصنيف البروتوكول (بوابة الصدق لكل ما بعدها)
| التصنيف | المعنى | العاقبة |
|---|---|---|
| `json` | أغلب الرسائل كائنات JSON | كل البطارية |
| `text` | نص بلا بنية JSON | تحليل محتوى فقط — العبث = `UNTESTABLE protocol_not_understood` |
| `binary`/`none` | إطارات ثنائية/صمت | `UNTESTABLE protocol_not_understood` — **لا ادّعاء ثغرة أبدًا** |

### البطارية
| الاختبار | الإثبات | التصنيف |
|---|---|---|
| اتصال غير موثَّق + بيانات حساسة | مستمع بلا اعتمادات يستقبل رسائل حساسة التسمية (token/session) | READ_ONLY |
| وصول عابر للهويات | ماركر هوية أخرى يظهر لرسائل المستمع غير المصرَّح | READ_ONLY |
| مصافحة مرفوضة | HTTP 401 دون اعتمادات → حد `TESTED` (المصادقة مفروضة) | READ_ONLY |
| replay حرفي | إعادة أول رسالة ملاحظة نصًّا (لا توليد، لا شكل جديد) | **STATE_CHANGING** — planner + `--logic-active` |

### قاعدة عدم التخريب
لا يتحول الماسح إلى fuzzing تخريبي: العبث مقيَّد بإعادة حرفية واحدة لبروتوكول
مفهوم؛ كل ما هو أبعد = حدود موثقة، وليس ثغرات مزعومة.
