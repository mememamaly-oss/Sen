## 2) الحملة الحية: OWASP Juice Shop 20.2.0 (هدف محلي مصرّح)

### 2.1 التجهيز
- السيرفر: الحزمة الرسمية المستخرجة، `node build/app` على :3000 (Node v24).
- هويات مسجلة للفحص: `sentinel41e@juice-sh.op` (id=25) و`sentinel41f@juice-sh.op`
  (كلمة سر test1234) + المدير الافتراضي `admin@juice-sh.op` (JWT RS256).
- مواصفة المشغّل OpenAPI: 19 مسارًا REST **بمعاملاتها المعلنة** (بما فيها `q`
  المصنفة search ومعرفات id ككائنات بيانات) — نفس نطاق التفويض الذي مُنح لحملة
  v4.0.0، مع تصويب مسار المراجعات إلى `/rest/products/{id}/reviews`.

### 2.2 المسح العميق الموثّق (run-7fcdb50bef)
`scan --allow-private --workflow --logic-active --auth-token <JWT> --auth-scheme Bearer
--openapi-spec <19 مسارًا>`

| المقياس | القيمة |
|---|---|
| الماسح | sentinel-core/**4.1.0** |
| المصادقة | token (Bearer JWT) — authenticated=True، رفضان مجهولين |
| النتائج | **30 مؤكدة → 29 فريدة بعد دمج البصمات** (دمج واحد) |
| التوزيع | 1 **حرجة** sql_injection + 28 منخفضة missing_security_headers |
| الطلبات/الزمن | 273 طلبًا / 39.4 ثانية |
| التغطية | 33 مكتشف = 33 مختبر (100% من المكتشف — لا ادعاء فوق ذلك) |
| الحدود | سجلّان NOT_DISCOVERED (graphql, websocket) بأسباب حرفية |
| التوأم | 83 عقدة / 49 حافة (بمصادر belief/provenance) |
| الاستدلال | 9 فرضيات مولدة → 9 مختبرة → **9 مرفوضة، 0 مؤكدة، 0 غير قابلة** |
| الإثباتات | 29 حزمة إثبات كاملة (فرضية/شروط/طلبات/استجابات/إعادة إنتاج) |
| الجرد | api_inventory: 28 واجهة REST بمصادر اكتشافها وحالة تغطيتها |
| المخطط | planner: تقييمات READ_ONLY مسموحة تلقائيًا؛ logic_active=on بالسياسة المعلنة |

**ملاحظة استدلالية حية (أهم ما يميز v4.1):** الفرضيات التسع كانت كلها نمط
R-TOKENLESS-WRITE على أسطح POST/DELETE (CSRF محتمل). اختبرها كاشف CSRF بإعادة
تشغيل عابرة للأصل — **ورُفضت التسع كلها بسبب صريح**: "الكاشف اكتمل ولم يُقبل
أي كتابة عبر الأصل" (Juice Shop تستخدم Bearer لا كوكيز ⇒ CSRF مخفف بنيويًا).
صفر نتائج كاذبة على هدف حي — **"المرفوض ليس نتيجة"** يعمل كما صُمم.

### 2.3 الثغرة الحرجة وإعادة إنتاجها
`F-5603a854b8 sql_injection (critical)` على `/rest/products/search?q=` —
مثبتة بفارق أوراكل: اقتباس→HTTP 500، اقتباس مضاعف→200، أساس→200.

**إعادة الإنتاج الحية من محرك نظيف** (`reproduce --replay`):
```
"replay": "REPRODUCTION_VERIFIED",
"reason": "the same vuln class re-verified on a clean engine",
"evidence": "quote -> HTTP 500 ... while base -> 200 and doubled-quote -> 200"
```
exit code 0. الدليل محفوظ حرفيًا في `juiceshop_replay_evidence.json`.

### 2.4 BOLA عبر المستخدمين (إثبات يدوي مصرّح)
`sentinel41e` (id=25) قرأ السلال 1–5 النائبة لمستخدمين آخرين — استجابات الـ200
تحمل `UserId: 1, 2, 3, 11, 16` في جسدها (دليل ملكية متناقض قابل لإعادة الإنتاج،
لا استنتاجًا). محفوظ في `juiceshop_bola_proof.json`. لماذا يدوي؟ انظر البند 21
بالجدول — محرك authz يعتمد تسجيل نماذج HTML وهذا الهدف JSON REST.

### 2.5 صدق التغطية والحدود على هدف حي
- **GraphQL:** probes المسارات المعروفة + استخراج JS + فحص شكل المسارات → لا
  نقطة نهاية → `NOT_DISCOVERED` بسبب حرفي. الهدف فعلًا لا يوفر GraphQL.
- **WebSocket:** كذلك → `NOT_DISCOVERED`.
- **سير العمل:** `--workflow` مُرَّر لكن المحرك قفز بشرف (`no_form_session` — SPA
  بلا نماذج HTML) وسجّل ذلك. مصفوفة القدرات تعرض الصف صفرًا بلا ادعاء.
- **الذاكرة الأمنية:** الجولة الثانية على نفس القاعدة استدعت بصمات الجولة الأولى
  (`juiceshop.db.memory.json`: جولتان، بصمات endpoints 28→29، سجل النتائج
  المؤكدة) — الذاكرة سياق لتقليل التكرار، ليست دليلًا أبدًا.

### 2.6 مصفوفة القدرات المولّدة آليًا
`capability-matrix` أنتج 15 صفًا من بيانات الجولة نفسها — REST 33/33/33، وصفوف
GraphQL/WebSocket/Workflow/Branching/State/Authorization أصفار بأسباب "لا سطح
لوحظ على هذا الهدف"، وحساب الحدود (سجلّان غير محلولين)، وعقد الصدق الثلاثة.
