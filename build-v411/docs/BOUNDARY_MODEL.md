# SENTINEL v4.1.0 — نموذج حدود المعرفة (Boundary Intelligence Model)

> المرجع التنفيذي لمحرك `boundary.py` — السجل الموحّد لما لم يستطع SENTINEL اختباره ولماذا.

## المبدأ

كل أداة أمنية تُخبرك بما وجدت. SENTINEL v4.1.0 يُخبرك أيضًا بما **لم يستطع** أن يجد،
ولماذا، وما الذي يمكنك فعله حيال ذلك. لا يوجد ادّعاء تغطية أو إثبات لم يحدث فعليًا.

## الحالات الـ14 الموحّدة

| الحالة | المعنى | هل تتطلب دليلاً؟ |
|---|---|---|
| `TESTED` | جرت محاولة ضد هذا البند | **نعم — إلزامي** |
| `VERIFIED` | أُثبت عيب بت证据 قابلة لإعادة الإنتاج | **نعم — إلزامي** |
| `REFUTED` | جرى الاختبار والهدف صمدّ | **نعم — إلزامي** |
| `UNTESTABLE` | البند موجود لكن شرطًا مسبقًا لاختباره لم يتحقق | لا |
| `NOT_DISCOVERED` | لم يُلاحظ أي بند من هذا النوع (بيان غياب) | **ممنوع** (الغياب لا يحمل دليلًا) |
| `NOT_SUPPORTED` | SENTINEL لا ينفّذ اختبار هذه الفئة | لا |
| `BLOCKED_BY_PERMISSION` | السياسة/الأعلام المطلوبة لم تُمنح | لا |
| `BLOCKED_BY_AUTH` | البند خلف مصادقة لا يملكها SENTINEL | لا |
| `BLOCKED_BY_SAFETY` | رفض مخطط الهجمات الآمن العملية (تخريبية/غير آمنة) | لا |
| `BLOCKED_BY_ENVIRONMENT` | بيئة التشغيل لا تستطيع الوصول للبند | لا |
| `TIMEOUT` | جرى استقصاء البند لكنه لم يجب خلال المهلة | **نعم — إلزامي** |
| `TOOL_FAILURE` | فشل SENTINEL نفسه أثناء الاختبار | **نعم — إلزامي** |
| `DEPENDENCY_MISSING` | تبعية خارجية مطلوبة غائبة (متصفح/حساب ثانٍ/توكن) | لا |
| `NOT_APPLICABLE` | فئة البند لا تنطبق على هذا الهدف/البروتوكول | لا |

## شكل السجل (كل عنصر غير مختبر)

```
BoundaryRecord(
    category,      # 'graphql/mutation', 'websocket/tampering', 'workflow/branch', ...
    target,        # 'POST /api/updateUser', 'wss://host/chat', 'flow#/branch plan=premium'
    state,         # واحدة من الـ14
    reason,        # السبب الصريح بالعربية/الإنجليزية — قابل للتحليل آليًا
    evidence,      # مرجع الملاحظة التي تبرر السجل (إلزامي لحالات الملاحظة)
    provenance,    # الوحدة + المسار الذي أنتج السجل
    remediation,   # ما يمكن للمشغّل فعله (عند توفره)
    seq, ts)       # ترتيب ثابت + وقت (متقلب موثّق)
```

## القواعد المفروضة (باختبارات)

1. **التحقق البنيوي** (`validate()`): أي سجل بحالة ملاحظة بلا دليل = فشل. أي
   `NOT_DISCOVERED` يحمل دليلًا = فشل. أي سجل بلا provenance أو reason = فشل.
2. **حارس النسبة الصادقة** (`honest_pct`): البُعد لا يدّعي 100% أثناء وجود سجل
   حدودي غير محلول في فئته — يُخفَّض الادعاء إلى 99.9 ويظهر السبب.
3. **الذاكرة ليست دليلًا**: السجلات المعاد بناؤها من جولات سابقة تُوسم
   `provenance=memory:*` ولا تُستخدم أبدًا لتغطية الجولة الحالية.

## التكامل

| المستهلك | ما يأخذه |
|---|---|
| Coverage 2.0 | `honest_pct` لكل بُعد + أسباب untested |
| التقارير (كل الصيغ) | قسم "Boundary Intelligence" الإلزامي — التنفيذي لا يخفي الحدود |
| CI/CD | `TOOL_FAILURE` ≠ 0 → exit 2 (فحص غير مكتمل) |
| Digital Twin | عقد `boundary` من الدرجة الأولى |
| بوابة عدم الهلوسة | `validate()` نظيف = شرط عبور |
