# SENTINEL v4.1.0 — بوابة عدم الهلوسة (No-Hallucination Gate)

> الاختبار القابل للتنفيذ (`unit_v41_no_hallucination_gate`) الذي يحول مبدأ
> "لا ادّعاء بلا دليل" إلى عقد برمجي مفروض.

## القواعد الست

| # | القاعدة | الفحص |
|---|---|---|
| G1 | لا نتيجة بلا دليل | كل finding في التقرير يحمل evidence غير فارغة |
| G2 | لا حقيقة مُلاحظة بلا provenance | `twin.belief_audit()` فارغ — كل عقدة/حافة تحمل belief + provenance |
| G3 | التغطية لا تدّعي tested > discovered | حساب كل بُعد سليم حسابيًا |
| G4 | القدرات الغائبة لا تُدّعى مختبرة | GraphQL/WebSocket: لا tested > 0 دون candidates > 0؛ بعد NOT_DISCOVERED لا يحمل tested |
| G5 | لا 100% مع بنود غير مختبرة غير مفسَّرة | pct == 100.0 ∧ untested > 0 = فشل |
| G6 | سجلات الحدود سليمة بنيويًا | كل سجل غير محلول يحمل سببًا (و`validate()` يُطبَّق في اختبارات المحرك) |

## للبوابة أسنان: الأكاذيب المزروعة تفشلها

البوابة ليست ديكورًا — الاختبار **يزرع أكاذيب في تقرير حقيقي ويثبت أن كل واحدة تفشل**:

| الكذبة المزروعة | النتيجة الإلزامية |
|---|---|
| نتيجة بلا دليل (`evidence: []`) | فشل G1 |
| بُعد graphql يحمل tested=3 بلا أي نقطة مكتشفة | فشل G4 |
| بُعد parameter: pct=100 مع بند untested غير مفسَّر | فشل G5 |
| بُعد endpoint: tested = discovered + 7 | فشل G3 |

## ما الذي يجعل هذا ممكنًا معماريًا

- **كل نتيجة** تمر عبر `VerificationEngine` (إعادة تشغيل مستقلة) قبل VERIFIED
- **كل عقدة توأم** تحمل `belief ∈ {observed, inferred, verified, refuted, unknown}`
  و`provenance` نصيًا — والاستدلال لا يوسم observed أبدًا
- **كل بُعد تغطية** مشتق من مسح فعلي لا من قوائم
- **كل سجل حدودي** يخضع لـ`validate()` (دليل إلزامي لحالات الملاحظة، ممنوع لدليل الغياب)
- **الذاكرة** سياق فقط — لا تُشبع أي ادعاء تغطية للجولة الحالية

## التشغيل

```bash
SENTINEL_TEST_FILTER=unit_v41_no_hallucination_gate python tests/run_tests.py unit
```

كما تعمل القواعد G2/G6 على كل تشغيل للجناح ضمن `regression_v41_full_platform`
(belief_audit فارغ + حدود سليمة في مسح كامل بمحركات v4.1 كلها).
