## الإصدار الحالي: v4.0.0 — من «قائمة ثغرات» إلى «نموذج معرفي قابل للاختبار»

القفزة المعمارية الكبرى: SENTINEL لم يعد يفحص التطبيق فقط — **يبني توأمًا
رقميًا أمنيًا** للتطبيق (رسمًا بيانيًا موحدًا)، **يولّد فرضيات هجوم من
أنماطه** (محرك استنتاج حتمي — بلا LLM ولا خدمات خارجية)، ثم **يثبت أو ينفي
كل فرضية** بنفس انضباط أوراكل الحالة الذي حافظ على F1=1.000 منذ 2.x، ويخرج
كل نتيجة كـ **ملف إثبات ذاتي** بوصفة إعادة إنتاج.

### الطبقات الجديدة الست

| الطبقة | الوحدة | ما تفعله |
|---|---|---|
| 🧠 **التوأم الرقمي** | `twin.py` | رسم بياني واحد يدمج كل ما اكتشفه الفحص: هويات/أدوار (الجلسات المُفعَّلة فعليًا)، أسطح (مصنفة READ/WRITE)، معاملات → **كيانات أعمال** (Order/Transaction/Account/Ticket…)، سير عمل → خطوات → حالات مع ربط mint/consume ومسارات التراجع، مصفوفة التفويض كحواف gates قابلة للإثبات، نتائج مربوطة بأسطحها، أسرار مقنعة، أسباب عدم الاختبار — **صفر طلبات إضافية** |
| 🔥 **محرك الاستنتاج** | `reasoning.py` | 10 أنماط فرضيات تُطابَق على التوأم (لا قوائم endpoints مبرمجة): «هذه الخطوة تولّد معرف كائن، وهوية ثانية موجودة → اختبر cross-identity». كل فرضية تحمل سلسلة استدلالها ووصفتها، ثم تُحلّ: verified / refuted / **untestable بسبب مقروء** — إثبات تغطية الاستنتاج |
| 🧬 **الهويات عبر الكائنات** | `workflow.py` (توسعة) | ثلاثة ثوابت جديدة تنضم للخمسة: **cross-user** (هوية ب تنفذ كائن هوية أ — مع كشف تصادم المعرفات بين مساحات منفصلة)، **cross-object** (تنفيذ كائن أجنبي النوع عبر سير عمل آخر)، **cross-state** (تنفيذ كائن ملغى عبر مسار التراجع). غياب الشرط المرئي = تخطٍ صادق مسموع لا يستهلك ميزانية |
| 🧪 **نظام الأدلة** | `evidence.py` | كل نتيجة = ملف إثبات: فرضية الهجوم ← الشروط المسبقة ← الطلبات ← الأدلة ← الهوية ← الحالة قبل/بعد ← الأثر ← **وصفة إعادة إنتاج خطوة بخطوة**. الأمر: `sentinel reproduce --finding F-xxx` |
| 🛡️ **مخطط الهجوم الآمن** | `planner.py` | كل عملية تُصنَّف قبل تنفيذها مع تفسير «لماذا»: قراءة (تلقائي) / أثر منخفض بقيم كنارية (تلقائي) / تغيير حالة (يتطلب `--logic-active`) / **تدميري (محجوب دائمًا)** — سجل قرارات قابل للتدقيق |
| 📊 **العرض والبوابة** | `report.py` + `cli.py` | **لوحة زجاجية عربية RTL** بأسلوب iOS (frosted glass) للتوأم، **تقرير تنفيذي** بلغة الخطر التجاري (تأثير البيانات/الجلسات/الصلاحيات)، SARIF بقواعد مستقرة SEN-BL-006/007/008، **بوابة CI/CD** (`report --ci` يخرج 1 عند وجود critical/high) |

## البدء السريع (v4.0.0)
```bash
unzip sentinel-4.0.0-source.zip -d sentinel && cd sentinel
python3 sentinel/cli.py doctor                       # 15/15
python3 sentinel/cli.py benchmark                    # F1 = 1.000 (38/0/0/35)
# فحص + توأم رقمي + فرضيات (آمن — تعلّم فقط):
python3 sentinel/cli.py scan <هدف-مصرح-به> --auth-user U --auth-pass P \
    --auth-url http://target/login --workflow --db results/run.db
# استعراض المنتجات الجديدة:
python3 sentinel/cli.py twin    --db results/run.db            # التوأم
python3 sentinel/cli.py report  --db results/run.db --format glass    --out twin.html
python3 sentinel/cli.py report  --db results/run.db --format executive --out exec.json --ci
python3 sentinel/cli.py reproduce --db results/run.db --finding F-xxxxxxxx
# البطارية الهجومية الكاملة (الثمانية — تغيّر حالة التطبيق، خيار صريح):
python3 sentinel/cli.py scan <هدف> ... --workflow --logic-active
```
