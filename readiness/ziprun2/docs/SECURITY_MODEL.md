# نموذج الأمن (Security Model) — SENTINEL v4.0.0

## المبادئ الخمسة

1. **الإثبات قبل الادعاء (Proof over Claim)** — كل Finding يمر عبر عدّالة تحقق
   مستقلة (إعادة إرسال ثنائية / تفاضل استجابة / عدّالة حالة / callback منسوب).
   المرشح المكذوب يُعرض ضمن "rejected candidates" — الشفافية تشمل الرفض.

2. **الحتمية (Determinism)** — بذرة واحدة + هدف واحد = فحص واحد قابل للتكرار
   بايت-بايت (الـBenchmark يثبت ذلك 3 مرات في كل إصدار). لا قرارات تعتمد على LLM
   أو على أي خدمة خارجية.

3. **الأمان بالتراجع المعلن (Loud Degradation)** — أي قدرة غير متاحة (مثلاً
   غياب playwright) تُعلن في doctor وفي السجلات؛ لا فشل صامت ولا نتائج ملفقة.

4. **أقل امتياز للفعل (Least-Action Privilege)** — خطة الهجوم تصنّف كل عملية:
   `READ_ONLY`/`LOW_IMPACT` تلقائيًا، `STATE_CHANGING` خلف `--logic-active`،
   `DESTRUCTIVE` محجوب دائمًا، وكل قرار يُسجَّل مع مبرره.

5. **الأسرار شفافة العرض فقط (Secrets are Mask-Only)** — القيم الخام تعيش حصريًا
   داخل Vault مشفّر (ChaCha20 encrypt-then-MAC)؛ كل واجهة أخرى ترى أقنعة.

## طبقات التحكم

| الطبقة | التحكم | الاختبار المثبت |
|---|---|---|
| التحقق | عدّالات مستقلة لكل صنف (VR-01..VR-20) | Benchmark FP=0 عبر 73 صفًا |
| الجلسات | ملفات تعريف منفصلة لكل هوية، إعادة دخول watchdog | D01–D12 |
| التفويض | مصفوفة دور×سطح + ملكية الكائن قبل أي Finding | E01–E16 |
| سير العمل | عدّالة حالة قبل/بعد لكل هجوم منطقي (VR-20) | F01–F18 |
| التخزين | SQLite WAL + كتابة ذرّية لكل run | Q02–Q14, X01–X10 |
| الخزنة | مفاتيح 0600، عزل مؤسسات، تدقيق مشفر، إتلاف موثق | K01–K14 |
| الواجهات | توكن إلزامي لغير loopback، 401 لكل مسار | R08/R09, S07/S08 |
| العرض | هروب كامل لمحتوى الهدف، لا أسرار خام | R14, T13 |
| التنفيذ | لا shell-out ببيانات هدف؛ chaos-proof | R12, R15 |

## عزل العملاء (Tenancy)

النموذج المعتمد: **نشر منفصل لكل عميل** (شجرة + DB + Vault + توكن REST خاصة
بكل عميل) — لا قناة اتصال بين النشرات أصلًا. داخل النشرة الواحدة يمكن فصل
مؤسسات متعددة عبر مغلفات Vault المستقلة (مفتاح لكل مؤسسة، وفشل صارم عند
المفتاح الخاطئ).

## دورة حياة الثغرة في الأداة نفسها (ENG)

كل عيب يُكتشف (داخليًا أو على هدف حي) يُصلح مع: اختبار وحدة للمكوّن + حارس
انحدار دائم في جناح الاختبار + إدخال في CHANGELOG. المجموع حتى v4.0.0:
ENG-01 … ENG-19 (أحدثها: ربط أزواج الحالة بالإثباتات، وتغطية التقارير).

## حدود المسؤولية

SENTINEL يُثبت ما يجده ولا يُثبت الغياب: النتائج "verified" مثبتة، والسطح غير
المختبر يُعرض صراحة مع أسبابه. التغطية 100% تعني "اختبرت كل ما اكتشفته" —
وليس "لا يوجد غير ما اكتشفته".
