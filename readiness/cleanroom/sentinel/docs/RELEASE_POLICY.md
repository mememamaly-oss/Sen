# سياسة الإصدارات — SENTINEL

## مخطط الإصدار (Semantic Versioning)

`MAJOR.MINOR.PATCH` — مثال: `4.0.0`

| الجزء | متى يرتفع | مثال |
|---|---|---|
| **MAJOR** | قدرة معمارية جديدة أو تغيير شكل للواجهات/التقارير | التوأم الرقمي والاستدلال (3.0→4.0) |
| **MINOR** | محرك/كاشف جديد أو توسعة سلوكية متوافقة | إضافة كاشف أو وضع مصادقة |
| **PATCH** | إصلاح عيب أو تحسين داخلي بلا تغيير واجهة | إصلاح مُكتشف على هدف حي |

## بوابات الإصدار (غير قابلة للتجاوز)

كل إصدار يُغلق فقط إذا اجتاز **كل** ما يلي:

1. **الجناح الكامل**: `tests/run_tests.py all` → 0 فشل (v4.0.0: 82/82).
2. **Doctor**: 15/15 (أو DEGRADED موثّق السبب في بيئة بلا playwright).
3. **الحتمية**: `sentinel benchmark` ثلاث مرات متتالية → مصفوفة TP/FP/FN/TN
   متطابقة + قوائم الصفوف متطابقة (v4.0.0: 38/0/0/35 ×3).
4. **F1 لا ينخفض** عن الإصدار السابق (v4.0.0: 1.000).
5. **الفحص من ZIP**: كل البوابات تُعاد من النسخة المضغوطة النهائية نفسها لا من
   شجرة التطوير.
6. **تثبيت نظيف**: استخراج source.zip وcomplete-bundle على بيئة معزولة (`env -i`)
   → doctor + فحص + تقارير + إعادة إنتاج، كلها خضراء.
7. **حملة حية**: تشغيل على الأهداف المصرّح بها (WebGoat/WebWolf/ginandjuice.shop
   + هدف مختلف معماريًا) بصمت بلا انحدار، وبلا إيجابيات كاذبة جديدة.

## سياسة العيوب (ENG)

كل عيب يُكتشف يحصل على معرّف `ENG-NN` ويُغلق بثلاثة: إصلاح + اختبار وحدة/انحدار
دائم + إدخال CHANGELOG. العيوب المكتشفة على أهداف حية لها الأولوية وتُصدر كـ
PATCH في أقرب دورة.

## محتويات كل إصدار

- `sentinel-<ver>-source.zip` — المصدر الكامل + الاختبارات + الوثائق + Benchmark.
- `sentinel-<ver>-complete-bundle.zip` — المصدر + نتائج البوابات المرجعية.
- `SENTINEL-FULL-ARCHIVE-<ver>.zip` — أرشيف واحد لكل إصدارات المصدر السابقة +
  الحزم + الوثائق (يُحتفظ بالأحدث فقط؛ الأرشيف الأقدم يُحذف بقرار مالك المنتج).
- `PRODUCTION_READINESS_<ver>.md` — سجل الجاهزية الكامل بالأدلة.

## مدة الدعم

- إصدار MAJOR الأخير: إصلاحات أمنية وإصلاحات عيوب حية.
- الإصدارات الأقدم: أرشيف فقط (المصادر متاحة داخل الأرشيف الكامل).
