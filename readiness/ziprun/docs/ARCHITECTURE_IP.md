## 1. الجملة الواحدة

**SENTINEL منصة DAST حتمية (deterministic) تبني توأمًا رقميًا أمنيًا للتطبيق، تولّد فرضيات هجوم من أنماطه، وتثبت كل نتيجة بدليل قابل لإعادة الإنتاج — بلا اعتماد على أي خدمة خارجية أو LLM.**

## 3. حواجز الدخول التقنية (ما يجعل الاستنساخ صعبًا)

1. **نظام الحتمية والتحقق المتعدد الجولات** — كل نتيجة تمر إعادة تشغيل مستقلة (fresh-input replay / differential oracle / victim-marker). بلوغ F1=1.000 مع 0 FP يتطلب سنوات تعديل أوراكلات — لدينا 18 عيبًا حركيًا (ENG-01..17 + أخرها) أُصلحت كلها من حملات حية ومحمية باختبارات انحدار دائمة.
2. **أوراكل الحالة لسير العمل** (state oracle): تعلم السلسلة → ربط الموارد (mint/consume) → مفردات التنفيذ (PENDING→EXECUTED) → البرهان بالفرق الكلمي بين لقطات حية بين الخطوات. هذه الآلية هي التي تجعل منطق الأعمال قابلًا للإثبات بدل التخمين.
3. **انضباط الشروط المسبقة المرئية**: هجمات cross-identity لا تُطلق إلا إذا كان **الشرط ملحوظًا في الواقع** (رؤية الكائن في oracle الهوية الأخرى، مسار تراجع في نماذج السير نفسه، كائن أجنبي الشكل في الـ oracle) — مع كشف تصادم المعرفات بين مساحات منفصلة (identifier collision detection). غياب الشرط = تخطٍّ صادق مسموع، أبدًا ليس تخمينًا.
4. **التوأم كطبقة موحدة**: كل المحركات تغذي رسمًا بيانيًا واحدًا بمعرّفات مستقرة، والاستنتاج يقرأ الأنماط منه — فتنتقل الفرضيات بين التطبيقات دون قوائم مبرمجة.
5. **أخلاقيات الأمان كمنتج**: planner مصنِّف مُعلَّل، تدميري محجوب افتراضيًا، أسرار مقنعة بالبناء (لا تدخل الرسم البياني أصلًا)، vault بتشفير مفاتيح وتدقيق كامل.

## 5. قابلية التدقيق (لماذا يثق المشتري)

- **حتمية كاملة**: نفس seed = نفس RunID = نفس النتائج (مثبت: run-3c0652b6be متطابق عبر التكرارات)
- **الحقيقة الأرضية v10**: 73 بندًا (38 موجب / 35 سالب) مع توائم آمنة لكل سطح مصاب — الفارق بين أداة تكرر ما تعرف وأداة تُختبر ضد ما تجهله
- **سجل هندسي**: كل عيب حركي (ENG-*) موثق بمسببه الحي وإصلاحه واختبار انحداره الدائم
- **إثبات التغطية**: لكل سطح غير مُختبر سبب مقروء (`requires_authentication`, `param_intel:json_object`, ...)
- **إثبات الاستنتاج**: للفرضيات غير القابلة للاختبار سبب مقروء — تغطية "لماذا لم نختبر" وليس فقط "ماذا اختبرنا"
