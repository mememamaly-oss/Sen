# نموذج التهديد (Threat Model) — SENTINEL v4.0.0

## 1. النطاق

SENTINEL أداة فحص تعمل عند المشغل (on-prem, CLI/REST). الأصول التي نحميها:

| الأصل | لماذا هو ثمين |
|---|---|
| بيانات دخول الأهداف | تفتح أنظمة إنتاج حقيقية |
| الأسرار المكتشفة من الأهداف | مفاتيح AWS/GitHub/URI قواعد بيانات حية |
| قاعدة النتائج | خريطة ثغرات كاملة للتطبيك المستهدف |
| تقارير/SARIF | نفس الخريطة بصيغة قابلة للتصدير |
| واجهة REST | تطلق فحوصات ويقرأ كل ما سبق |

## 2. سطوح الهجوم (Attack Surfaces) والتحكمات

### S1: بيانات الاعتماد في الذاكرة/السجلات
- **التهديد:** تسريب كلمات مرور الأهداف إلى logs/تقارير/استثناءات.
- **التحكم:** بيانات الدخول وسائط سطر أوامر تُستخدم في الطلب فقط؛ لا تُسجَّل ولا
  تُخزَّن؛ رسائل أخطاء المصادقة تحمل الحالة/العدّالة فقط. (اختبارات: D09/D10/R03)

### S2: الأسرار المكتشفة
- **التهديد:** ظهور قيمة خام (AKIA…/ghp_…) في DB/تقرير/SARIF/log.
- **التحكم:** القيم الخام تُشفَّر فورًا داخل Vault (ChaCha20 + HMAC، مفتاح 0600)
  وكل المخرجات تحمل أقنعة؛ عند تسليح الخزنة تُنظَّف التقارير بأكملها من أي قيمة
  معروفة (defense-in-depth). الكشف الكامل للمالك فقط عبر `vault report` مسجَّلًا
  في سجل تدقيق مشفر. (اختبارات: K01–K14، R04/R05)

### S3: واجهة REST
- **التهديد:** الوصول غير المصرح به للنتائج أو إطلاق فحوصات.
- **التحكم:** الربط غير loopback يتطلب `--token` إلزاميًا، وكل مسار يتحقق من
  `X-Auth-Token` (401 عند الغياب/الخطأ). (اختبارات: R08/R09، S07/S08)

### S4: محتوى الهدف الخبيث (anti-attack-the-scanner)
- **التهديد:** محتوى استجابة خبيث يكسر SENTINEL أو يحقن في تقاريره (stored XSS).
- **التحكم:** كل نص من الهدف يُهرَّب (`html.escape`) عند العرض؛ لا تنفيذ لأي
  شيء من بيانات الهدف؛ مسار الملفات لا يتأثر ببيانات الهدف أبدًا؛ chaos suite
  يثبت الصمود أمام garbage/huge/resets/timeouts. (اختبارات: R10–R15)

### S5: حقن أوامر
- **التهديد:** وصول هدف إلى تنفيذ أوامر محلية.
- **التحكم:** مراجعة shell-out: `subprocess` فقط لمسارات ثابتة (`sys.executable`
  + ملفات الشجرة)؛ لا interpolation لأي بيانات هدف. (اختبار: R12)

### S6: OAST
- **التهديد:** callbacks مزيّفة تنسب ثغرة عمياء لأهداف بريئة، أو تجاوز العزل.
- **التحكم:** كل تفاعل يُنسب فقط لمعرّف حمولة أطلقها المحرك نفسه (حارس ENG-08)،
  والخادم لا ينفذ شيئًا من محتوى الـcallback. (اختبارات: L03/L04، R13)

### S7: سلامة العمل تحت القتل/الانهيار
- **التهديد:** قتل العملية أثناء الفحص → قاعدة فاسدة أو نتائج نصف مكتوبة.
- **التحكم:** SQLite WAL + كتابة ذرّية لكل run (all-or-nothing)؛ الأدلة السابقة
  لا تتأثر بقتل فحص لاحق. (اختبارات: Q02–Q14، X01–X10)

### S8: الاستخدام المسيء للأداة نفسها
- **التهديد:** تشغيل بطاريات مغيّرة للحالة على هدف حي بلا تصريح.
- **التحكم:** الهجمات المنطقية خلف `--logic-active` مع تحذير صاخب؛ المصنَّف
  DESTRUCTIVE محجوب دائمًا؛ READ_ONLY/LOW_IMPACT فقط تعمل تلقائيًا. (اختبارات: P01–P10)

## 3. خارج النطاق (Out of Scope)
- حماية المشغل من نفسه (اختيار مسارات `--out` خارج مجلد العمل ميزة مشروعة).
- إدارة مفاتيح المؤسسة (تسليم `owner.key` مسؤولية إجرائية عند العميل).
- الفحص السلبي لحركة مرور الإنتاج (SENTINEL فاحص نشط بموافقة).

## 4. افتراضات
1. المشغل مصرّ له بفحص الهدف (الاستخدام المصرح به فقط).
2. جهاز المشغل نفسه غير مخترق (خارج نموذجنا).
3. قناة OAST العامة موثوقة للتسليم فقط (لا للسرية — لا تُرسل عبرها أسرار).
