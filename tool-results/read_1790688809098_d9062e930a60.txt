     7→## What v2.7.0 adds (Phase 55 — five new verified vulnerability classes)
     8→
     9→1. **SSTI — Server-Side Template Injection (DETECT-15, CRITICAL)**
    10→   Template-syntax arithmetic battery across the four dominant families
    11→   ({{ }} Jinja2/Twig, ${ } FreeMarker/EL, <%= %> ERB, #{ } Ruby/Thymeleaf).
    12→   Oracle: the COMPUTED result (49) appears in the response while the literal
    13→   expression does NOT — raw echo is reflection, never evaluation. VR-12
    14→   re-tests the winning syntax family with fresh operands ({{12*11}} -> 132):
    15→   ambient page numbers cannot reproduce a fresh computation.
    16→
    17→2. **CSRF — cross-origin acceptance (DETECT-16, MEDIUM)**
    18→   State-changing POST forms carrying NO anti-CSRF token are replayed with a
    19→   hostile Origin+Referer. The oracle is acceptance: the cross-origin request
    20→   must succeed like the same-origin baseline (same status, similar body).
    21→   Honesty gates: token-bearing forms skipped outright, read-only surfaces
    22→   (stock/search/login) skipped, 401/403-gated baselines skipped (no honest
    23→   anonymous oracle). VR-13 re-tests with a FRESH hostile origin.
    24→
    25→3. **NoSQL operator injection (DETECT-17, CRITICAL)**
    26→   JSON-body endpoints where a $-operator object ({"$ne": "x"}) flips a
    27→   REJECTED baseline into an ACCEPTANCE — the Mongo auth-bypass shape. Full
    28→   JSON bodies ride engine body_override. VR-14 re-tests with a DIFFERENT
    29→   operator ($gt after $ne).
    30→
    31→4. **JWT unsigned-issuance analysis (DETECT-18, MEDIUM)**
    32→   Auth-shaped endpoints are replayed benignly; responses (body + Set-Cookie)
    33→   are mined for JWTs. An issued token with alg=none and an EMPTY signature is
    34→   a defect by RFC 8725 §3.1. Signed issuance (HS256/RS256) is normal and stays
    35→   silent. VR-15 = fresh replay must issue another none-token.
    36→
    37→5. **Host header injection (DETECT-19, MEDIUM)**
    38→   A canary Host header on GET HTML endpoints; reflection into the response
    39→   (Host-built absolute links — the reset-poisoning class) is the oracle.
    40→   VR-16 re-tests with a FRESH canary host.

    93→## What v2.6.0 adds (stealth + ops + intelligence axes)
    94→
    95→1. **Passive WAF + technology fingerprinting (`sentinel/fingerprint.py`)**
    96→   Two observers that ride every response the scan already produces — zero
    97→   extra requests. WafFingerprinter matches named WAF signatures (Cloudflare,
    98→   AWS WAF, ModSecurity, F5, Imperva, Sucuri, Akamai, Fastly) from headers,
    99→   cookies and block-page bodies, with the evidence line each conclusion came
   100→   from. TechFingerprinter maps Server/X-Powered-By/X-AspNet-Version headers,
   101→   session-cookie platforms (JSESSIONID->Java, PHPSESSID->PHP, ...), DOM markers
   102→   (ng-app, __VIEWSTATE, wp-content) and meta generators. Honesty contract: no
   103→   signature hits -> waf null ("no WAF seen" is NOT a claim the passive channel
   104→   can make); x-amzn-requestid is deliberately NOT aws-waf (infra header —
   105→   false-attribution guard). stats.fingerprint lands in every report.
   106→
   107→2. **DETECT-14 context-adaptive XSS battery (`sentinel/detect.py`)**
   108→   ONE benign known-tag probe per mutable param classifies the input context:
   109→   tag-filtered (400/403 on a plain <b>) -> attribute-injection battery (no '<'
   110→   at all); ng-app in the page -> + AngularJS {{expression}} vector; plain ->
   111→   classic full-tag + slash-free battery. LIVE-PROVEN on ginandjuice.shop:
   112→   the ng vector found a REAL Angular expression reflection on /catalog
   113→   (param searchTerm) that every previous version missed — verified via
   114→   re-test:fresh-ng-expression. (The /blog?search attr-inject vector that
   115→   inspired the "filtered" arm was already live-proven in v2.2.0.)
   116→
   117→3. **ENG-09 rate-limit resilience (`sentinel/http_engine.py`)**
   118→   429/503 answers are a WAF/CDN saying "slow down", not an app response.
   119→   Deterministic exponential backoff (0.4 * 2^n, cap 8s, max 3 retries),
   120→   Retry-After honored when present, the request replayed IDENTICALLY
   121→   (determinism preserved), and the final 429 returned HONESTLY if the limiter
   122→   never relents (never a fabricated error). stats.rate_limit carries
   123→   limited/retries/recovered for audit.
   124→
   125→4. **AUTH-05 static-token authentication (`sentinel/auth.py`)**
   126→   Bearer JWTs, API keys, custom headers (X-Auth-Token). "Login" = VALIDATION:
   127→   fetch the validation URL WITH the header and require a door that is closed
   128→   without it (401/403 rejected, login-gate bounce detected, optional success
   129→   marker). The token rides engine.default_headers — every request carries it
   130→   with zero per-phase wiring. No self-healing by design (a static token cannot
   131→   be re-minted): mid-scan 401/403 are COUNTED honestly (stats.auth.rejections)
   132→   instead of silently proceeding anonymous. CLI: --auth-token / --auth-header /
   133→   --auth-scheme / --auth-validate-url. LIVE-PROVEN against ginandjuice.shop
   134→   (header rides a real TLS target, scan completes, honest counters).
   135→
   136→5. **DISC-13 OpenAPI/Swagger seeding (`sentinel/discovery.py`)**
   137→   The target's own machine-readable surface map: auto-probe /openapi.json,
   138→   /swagger.json, /swagger/v1/swagger.json, /v2/api-docs (or an explicit
   139→   --openapi-spec file/URL) — unlinked admin/legacy/API paths invisible to any
   140→   crawler are declared there with parameters (query, path, JSON body fields).
   141→   Seeded endpoints ride the SAME dedup + scope gates as crawl results. Honest
   142→   negative recorded (stats.openapi) when no document exists. LIVE on
   143→   ginandjuice.shop: no document — honest null.
   144→
   145→6. **OP-02 SARIF 2.1.0 export (`sentinel/report.py`)**
   146→   The industry interchange format (GitHub code scanning, VS Code, DefectDojo).
   147→   Stable rule registry (a finding type always maps to the same SEN-XXX ruleId
   148→   so runs diff cleanly), severity->level mapping, verification-gated (rejected
   149→   candidates NEVER become results), evidence chain + verification method as
   150→   properties, partialFingerprints for result tracking. CLI: report --format
   151→   sarif; REST: GET /api/runs/<id>/sarif. LIVE: the full ginandjuice.shop
   152→   production run exports 34 results across 7 rules.
   153→
   154→7. **Test-runner fast filter (ops)**
   155→   SENTINEL_TEST_FILTER=prefix1,prefix2 executes only matching cases (cases run
   156→   at import in this runner; a "filtered" CLI run used to pay the full suite
   157→   runtime anyway). Release gate still runs the full suite.

   192→## What v2.5.0 adds (detector hardening: SSRF / blind command injection / CORS)
   193→
   194→1. **SsrfDetector — DETECT-11 (`sentinel/detect.py`)**
   195→   Server-side request forgery on URL-carrier params (name- or value-gated),
   196→   confirmed OUT-OF-BAND over the OAST channel (the evidence pattern proven for
   197→   blind XXE in v2.4.0): the probe points the param at the listener; a callback
   198→   is server-side fetch proof. Deterministic probe budget (12); inert without an
   199→   armed channel (response-only SSRF oracles are ambient noise — live-observed).
   200→   Verification **VR-09**: fresh interaction id replay.
   201→
   202→2. **CommandInjectionDetector — DETECT-12**
   203→   Blind OS command injection: a 2-variant shell-separator battery (`;` and `&&`
   204→   chaining `curl` to the listener) across mutable params (deterministic budget,
   205→   24 params). A callback proves code left the app's shell. Verification
   206→   **VR-11**: fresh interaction id + DIFFERENT syntax (`|` chaining) — execution
   207→   must reproduce through an independent separator.
   208→
   209→3. **CorsDetector — DETECT-13**
   210→   One header-only probe per GET endpoint: arbitrary-Origin reflection in
   211→   Access-Control-Allow-Origin combined with Access-Control-Allow-Credentials:
   212→   true (the dangerous pair; ACAO:* without credentials is NOT reportable).
   213→   Verification **VR-10**: the reflection must repeat on a FRESH origin value.
   214→
   215→4. **ENG-08 self-callback guard (live-caught during this build)**
   216→   The v2.5.0 SSRF detector immediately exposed a real trap on fixture
   217→   /vuln/redirect.php: the engine follows SAME-HOST redirects (required for auth
   218→   landings), so an open-redirect target bounces the probe URL back at the
   219→   listener and the SCANNER ITSELF performs the fetch — a would-be SSRF false
   220→   positive (callback UA = engine UA; hop present in redirect_chain). Both
   221→   OAST-channel detectors and the XXE path now reject scanner-initiated
   222→   callbacks; the engine UA is version-derived (also fixes the stale hardcoded
   223→   "Sentinel/2.2" fingerprint). Permanent regression:
   224→   regression_eng08_self_callback_guard (true fetch found, redirect twin silent).
   225→
   226→5. **Risk model + registry**: command_injection=9, ssrf=7, cors_misconfig=6 in
   227→   RISK_WEIGHTS; 9 active detectors (doctor detector_registry updated).

   288→   lack of a listener). CLI: `scan --oast auto|local|public` (default auto).

   290→3. **Stats transparency — `stats.oast`**
